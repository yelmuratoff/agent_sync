# Git Rules

## Commits

- Write commit messages in imperative mood: "Add feature", not "Added feature".
- Use conventional prefixes: `feat:`, `fix:`, `refactor:`, `test:`, `chore:`, `docs:`.
- First line: concise summary under 72 characters.
- One logical change per commit. Don't mix tool config changes with sync engine changes.

## Branches

- Use descriptive branch names: `feat/add-zed-support`, `fix/yaml-parser-quoting`, `refactor/split-sync-helpers`.
- Keep branches short-lived. Rebase against `main` before merging.

## What Not to Commit

- Never commit generated output directories (`.claude/`, `.cursor/`, `.github/copilot-instructions.md`, etc.) — these are in `.gitignore` for the `example/` dir.
- Don't commit `.env`, credentials, or OS-specific files (`.DS_Store`).
- The `example/` output dirs are gitignored — they're regenerated by `agentsync sync`.

## Pull Requests

- Keep PRs focused. Tool config changes, sync engine changes, and test changes can be in one PR if they're related.
- Include "how to test" instructions — which `bats` files to run.
- Don't force-push to shared branches.
