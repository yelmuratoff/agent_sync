# Git Rules

## Commits

- Write commit messages in imperative mood: "Add feature", not "Added feature".
- Use conventional prefixes: `feat:`, `fix:`, `refactor:`, `test:`, `chore:`, `docs:`.
- First line: concise summary under 72 characters.
- One logical change per commit. Split tool-config changes and sync-engine changes into separate commits.

## Branches

- Use descriptive branch names: `feat/add-zed-support`, `fix/yaml-parser-quoting`, `refactor/split-sync-helpers`.
- Keep branches short-lived. Rebase against `main` before merging.

## Keep Out of Commits

- Leave generated output directories (`.claude/`, `.cursor/`, `.github/copilot-instructions.md`, etc.) out of git — they're regenerated by `agentsync sync` and gitignored under `example/`.
- Keep `.env`, credentials, and OS-specific files (`.DS_Store`) out of the repo.
- Treat `example/` output dirs as ephemeral; regenerate them via `agentsync sync` rather than committing.

## Pull Requests

- Keep PRs focused. Tool config changes, sync engine changes, and test changes can ride together when they're part of the same logical change.
- Include "how to test" instructions — which `bats` files to run.
- Coordinate before force-pushing a shared branch; prefer additive commits for in-flight work.
