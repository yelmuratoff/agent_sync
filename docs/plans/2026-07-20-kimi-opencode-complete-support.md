# Kimi Code and OpenCode Complete Support Implementation Plan

> Execute with `subagent-driven-development` only when the user explicitly authorizes subagents/delegation; otherwise execute inline. Steps use `- [ ]` for tracking.

**Goal:** Complete safe project-level AgentSync coverage for Kimi Code and OpenCode by adding atomic OpenCode MCP composition, native OpenCode hooks, explicit ownership diagnostics, and accurate capability documentation.

**Architecture:** Keep the existing `agents/rules/skills/commands/subagents/settings/mcp/hooks` target model. Verify every slice through the existing CLI-level Bats seam: initialize a temporary project, enable OpenCode or Kimi, run the public command, and assert generated files plus exit behavior. Add one OpenCode-specific pure Bash/AWK adapter rather than a generic passthrough subsystem.

**Tech stack:** Bash 3.2-compatible shell, POSIX AWK, Bats, Git; no Python, Node, `jq`, or `yq` at runtime.

## Global Constraints

- `.ai/src/` remains the source of truth.
- Generated outputs remain drift-protected and idempotent.
- The CLI keeps its zero-runtime-dependency contract: Bash, standard Unix tools, and Git only.
- Unsupported or ambiguous input fails explicitly; sync never drops fields or overwrites one source with another silently.
- AgentSync does not own credentials, UI preferences, arbitrary OpenCode custom tools, arbitrary third-party plugins, or Kimi's global runtime home.
- OpenCode canonical MCP input uses `{ "mcpServers": { ... } }`; generated output uses the top-level `mcp` field in `opencode.json`.
- A canonical OpenCode MCP source and an `mcp` field in the settings source are mutually exclusive.
- OpenCode hook ownership is limited to `.opencode/plugins/agentsync.ts`; sibling plugins are preserved.
- Kimi hooks remain global-only and are never generated by a project sync.

- [x] **Step 4: Implement the atomic composer**

Create `lib/helpers/opencode.sh` with this public contract:

```bash
#!/usr/bin/env bash

sync_opencode_config() {
    local settings_src="$1"
    local mcp_src="${2:-}"
    local dest="$3"
    local dry_run="${4:-false}"
    local tmp
    tmp=$(mktemp "${TMPDIR:-/tmp}/agentsync_opencode.XXXXXX") || return 1

    if ! _opencode_compose_json "$settings_src" "$mcp_src" "$tmp"; then
        rm -f "$tmp"
        return 1
    fi
    if [[ "$dry_run" == "true" ]]; then
        rm -f "$tmp"
        log_step "Would compose OpenCode settings and MCP → $(display_path "$dest") (dry-run)"
        return 0
    fi

    ensure_dir "${dest%/*}"
    mv "$tmp" "$dest"
    declare -f manifest_record_write >/dev/null 2>&1 && manifest_record_write "$dest"
}
```

Implement `_opencode_compose_json` as one POSIX AWK state machine adapted from `_add_mcp_merge`. It must:

```text
1. Parse the root settings object and preserve every raw top-level value.
2. Parse the root mcpServers object.
3. For each local server require command:string, allow args:string[], env:object,
   type:"stdio", enabled:boolean, timeout:number.
4. Emit type:"local", command:[command,...args], environment:env.
5. Replace or append only the top-level mcp field.
6. Write the complete JSON document to the provided temporary output.
```

Use an AWK exit code map so stderr names the cause:

```text
20 malformed settings JSON
21 malformed canonical MCP JSON
22 mcpServers is not an object
23 invalid server object or field type
24 settings already owns mcp while canonical MCP is active
25 unsupported field
26 command and url both present, or neither present
```

`sync_opencode_config` translates each code into `log_error` output containing the source path and, where available, the server and field from an AWK diagnostic side file.
